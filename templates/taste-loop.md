# Taste Loop Template

Turn Oleena's corrections into gold examples and yes/no checks. Run these checks before sending work for approval.

## How to capture a correction

When Oleena edits your work, rewrites a line, or rejects something with a reason:

1. **Apply the edit first.** The work comes before the bookkeeping.
2. **Save the correction** using the gold example template below.
3. **Write one check per distinct correction** (usually one to three checks per correction).
4. **Confirm** in one line: "Saved as a gold example. New check: [describe the check]."

Don't save these:
- A fact that applies only to this piece (this week's specific promo date)
- A standing rule already stated elsewhere (documented brand voice rules)
- An edit Oleena calls a one-off

## Gold example template

```markdown
# [Short name]

- Date: 2026-11-16
- Lead: [Marketing Lead, Creative Lead, etc.]
- Request: "[what was asked, in Oleena's words]"

## What I produced
[only the parts that changed, verbatim]

## What shipped
[Oleena's final version of those parts, verbatim]

## Why
> "[Oleena's words]"

## Checks added
- Does it [specific yes/no question derived from this correction]?
```

## Writing a good check

- **Yes means good.** "Does the headline use the customer's words?" not "Does it use jargon?"
- **One idea per check.** Split compound corrections into separate checks.
- **Checkable by reading the work alone.** Specific enough that two people would give the same answer. "Is it punchy?" fails this test. "Is every sentence under 20 words?" passes it.
- **General enough to apply next time.** Write the rule the edit stands for, not the edit itself.
- **From a real correction only.** Never invent checks Oleena didn't give you.
- **No duplicates.** Check existing checks before adding a new one. Sharpen an existing check rather than creating a near-duplicate.

## Pre-send checklist

Before presenting work to Oleena, answer each relevant check yes or no. Rewrite until every answer is yes. Do this silently — never show the list or scores in your deliverable.

If a check conflicts with what Oleena asked for today, today's request wins. Note it in one line in your Sources and assumptions.
